# СтандартныеОшибки

Стандартные коды универсальны: они не получают пространство имён библиотеки-потребителя.
Благодаря этому разные библиотеки могут одинаково обрабатывать инфраструктурную ошибку.
Для наиболее востребованных кодов доступны именованные фабрики в
`СтандартныеОшибки` и `ПостроителиСтандартныхОшибок`.

## Общий контракт

Все функции возвращают готовую `ИнформацияОбОшибке` и не выбрасывают созданную предметную ошибку. Общая сигнатура:

```bsl
Ошибка = СтандартныеОшибки.<ИмяФабрики>(<ДиагностическиеПараметры>, <Сообщение> = "");
```

Диагностические параметры перечислены в столбце `Поля Данные` каталога и передаются в том же порядке.
Сигнатуры с несколькими диагностическими параметрами:

```bsl
Ошибка = СтандартныеОшибки.НеверныйТипАргумента(
    <ИмяАргумента>,
    <ОжидаемыйТип>,
    <ФактическоеЗначение>,
    <Сообщение> = ""
);
Ошибка = СтандартныеОшибки.НедопустимоеЗначениеАргумента(
    <ИмяАргумента>,
    <Ожидание>,
    <Сообщение> = ""
);
Ошибка = СтандартныеОшибки.АргументВнеДиапазона(
    <ИмяАргумента>,
    <ОжидаемыйДиапазон>,
    <Сообщение> = ""
);
Ошибка = СтандартныеОшибки.ДанныеСлишкомБольшие(
    <ИмяДанных>,
    <Ограничение>,
    <Сообщение> = ""
);
Ошибка = СтандартныеОшибки.ДанныеНеСоответствуютКодировке(
    <ИмяДанных>,
    <Кодировка>,
    <Сообщение> = ""
);
```

У `НеверныйТипАргумента()` в данные записывается строковый `ФактическийТип`, а не фактическое значение.

## Использование

`СтандартныеОшибки` возвращает готовую `ИнформацияОбОшибке` без дополнительного
`Построить()`:

```bsl
Ошибка = СтандартныеОшибки.РесурсНеНайден("config.json");
```

`ПостроителиСтандартныхОшибок` возвращает настроенный `ПостроительОшибки`, который можно
обогатить дополнительными данными, подсказкой и URL:

```bsl
Ошибка = ПостроителиСтандартныхОшибок.РесурсНеНайден("config.json")
    .Данные("Каталог", КаталогНастроек)
    .Подсказка("Проверьте путь к файлу")
    .URL("https://example.org/errors/resource.not_found")
    .Построить();
```

Для обработки ошибок без строковых литералов используйте одноимённые функции
[`КодыСтандартныхОшибок`](КодыСтандартныхОшибок.md):

```bsl
Если Разбор.Ошибки().Содержит(КодыСтандартныхОшибок.РесурсНеНайден()) Тогда
    // Обработка отсутствующего ресурса
КонецЕсли;
```

## Выбор близких кодов

- `access.unauthenticated` означает отсутствие действительных учётных данных. `access.denied` используется, когда
  вызывающая сторона определена, но не обладает необходимыми правами.
- `resource.closed` означает попытку использовать локально закрытый или освобождённый объект.
  `connection.aborted` означает неожиданное прекращение ранее установленного соединения, а
  `connection.not_connected` - отсутствие требуемого установленного соединения.
- `connection.reset` используется для сброса соединения удалённой стороной или сетевым стеком, а
  `connection.aborted` - для его неожиданного прекращения без более точной причины.
- `network.name_not_found` означает ошибку разрешения сетевого имени, `network.host_unreachable` - недостижимость
  конкретного узла, а `network.unreachable` - отсутствие доступной сети или маршрута в целом.
- `dependency.unavailable` называет временно недоступный внешний компонент. `operation.unavailable` используется,
  когда значимой частью контракта является сама временно недоступная операция.
- `resource.exhausted` означает общее исчерпание ёмкости ресурса, `resource.quota_exceeded` - превышение выделенной
  потребителю квоты, а `operation.rate_limited` - превышение количества операций за период времени.
- `operation.conflict` означает конфликт версии, конкурентного изменения или транзакционного состояния. Обычно
  обработчику требуется перечитать состояние и повторить последовательность операций целиком.
- `resource.not_empty` означает невыполненное предусловие удаления или очистки ресурса.

Возможность повторить операцию зависит от её идемпотентности и контекста. Сам код ошибки не разрешает автоматически
повторять операцию.

## Ошибки

Все диагностические параметры именованных фабрик и `Сообщение` - строки;
диагностические параметры должны быть непустыми. Исключение - `ФактическоеЗначение`
функции `НеверныйТипАргумента`, оно может иметь любой тип.

| Код | Условие |
| --- | --- |
| `argument.invalid_type` | Диагностический параметр или `Сообщение` имеют недопустимый тип |
| `argument.required` | Обязательный диагностический параметр не заполнен |

Функции `СтандартныеОшибки` возвращают `ИнформацияОбОшибке`, совместимую с `ВызватьИсключение`, а функции
`ПостроителиСтандартныхОшибок` - настроенный `ПостроительОшибки`.

Фабрики сохраняют только перечисленные в таблице поля. Фактические значения, содержимое
данных, исходные исключения, сетевые ответы, полные URI и реквизиты доступа автоматически
не записываются. Имена ресурсов, узлов и другие диагностические строки передавайте в
безопасном для журналирования виде.

Стандартные сообщения заданы через `НСтр` на русском и английском языках. Вариант
выбирается настройкой OneScript `systemLanguage` (`ru` или `en`); машинный код ошибки при
этом не меняется. Можно передать собственное сообщение последним параметром фабрики.
