# Маркер единственного контекста

## Цель

Упростить подробное представление ошибки: не выводить маркер `-` перед единственным
контекстом. Если в блоке два или более контекстов, каждый из них по-прежнему начинается с `-`.

## Область изменения

Правило применяется ко всем блокам контекстов в подробном представлении:

- `Контекст:` у группы ошибки;
- `Контекст без просмотренной причины:`.

Краткое представление ошибки не меняется.

## Реализация

В месте, где формируется блок контекстов, определяется маркер:

- пустая строка для одного контекста;
- `- ` для двух или более контекстов.

Выбранный маркер передаётся в существующую процедуру добавления контекста. Отступ
дополнительных полей контекста учитывает длину маркера, чтобы сохранить выравнивание.

## Тестирование

Изменение выполняется через TDD:

1. Тест обычного блока с одним контекстом ожидает строку без `-`.
2. Тест блока без просмотренной причины с одним контекстом ожидает строку без `-`.
3. Существующие тесты с несколькими контекстами подтверждают сохранение `-`.
4. После точечной проверки запускается весь набор `oneunit execute`.

## Критерии готовности

- единственный контекст в любом подробном блоке выводится без `-`;
- два или более контекстов выводятся с `-`;
- многострочные сообщения и дополнительные поля остаются выровнены;
- краткое представление не меняется;
- все тесты проходят.
