# Класс снимка кадра ошибки

## Цель

Устранить неоднозначность термина «кадр»: физический кадр остаётся объектом
`ИнформацияОбОшибке`, а его безопасное публичное представление становится объектом
`СнимокКадраОшибки`.

## Публичный API

Класс `СнимокКадраОшибки` располагается в `src/Классы` и является публичным.
Потребитель может создать его напрямую:

```bsl
СнимокКадра = Новый СнимокКадраОшибки(Ошибка);
```

Конструктор принимает ровно один аргумент типа `ИнформацияОбОшибке`. Для значения
другого типа выбрасывается исключение с тем же сообщением, которое используют
публичные методы диагностики.

Все переменные класса приватные. Класс предоставляет экспортные геттеры:

```text
Вид()
ТипОшибки()
Сообщение()
Данные()
ИмяМодуля()
НомерСтроки()
ИсходнаяСтрока()
Стек()
```

Сеттеров и экспортных переменных нет.

## Семантика значений

- `Вид()` возвращает `Ошибка`, `Контекст` или `ВнешняяОшибка`.
- `ТипОшибки()` заполнен только для распознанного кадра вида `Ошибка`.
- `Данные()` заполнены только для распознанных собственных кадров видов `Ошибка`
  и `Контекст`; чужие параметры не раскрываются.
- `Сообщение()`, `ИмяМодуля()`, `НомерСтроки()` и `ИсходнаяСтрока()` относятся к
  переданному физическому кадру.
- Недоступное необязательное скалярное свойство возвращается как `Неопределено`.
- `Стек()` всегда возвращает новый массив. Если стек недоступен, массив пустой.
- `Данные()` возвращает исходное произвольное значение без глубокого копирования.
- Исходная `ИнформацияОбОшибке` не предоставляется через публичный интерфейс класса.

После завершения конструктора сохранённые скалярные значения не изменяются.
Массив стека защищён копированием при сохранении и при каждом чтении.

## Изменение структурного представления

`ДиагностикаОшибок.ВСтруктуру(Ошибка)` продолжает возвращать верхнеуровневую
`Структура`, но набор её полей изменяется на:

```text
ТипОшибки
Усечена
СнимкиКадров
```

`СнимкиКадров` — новый массив объектов `СнимокКадраОшибки` в физическом порядке
от внешнего кадра к корневому. Поле `Кадры` удаляется. Версия в результат не
добавляется.

## Внутренняя архитектура

`ВнутреннееУстройствоОшибок.ПросмотретьЦепочку()` остаётся единственным механизмом
обхода цепочки, определения порядка и признака усечения. Его внутренние описания
по-прежнему содержат исходный кадр, поскольку он необходим методам `НайтиОшибку()`
и `Цепочка()`.

Класс самостоятельно строит снимок переданного кадра. Для распознавания envelope
он вызывает служебную экспортную функцию внутреннего модуля. Логика проверки
маркера, вида, типа и обязательных полей не дублируется в классе.

`ДиагностикаОшибок.ВСтруктуру()` получает результат `ПросмотретьЦепочку()` и создаёт
`Новый СнимокКадраОшибки(ОписаниеКадра.Кадр)` для каждого просмотренного кадра.
Отдельная экспортная функция `СоздатьСнимок()` во внутреннем модуле удаляется.

## Обработка ошибок

Неверный тип аргумента конструктора отклоняется строго. Повреждённые или чужие
метаданные корректной `ИнформацияОбОшибке` не приводят к исключению: кадр получает
вид `ВнешняяОшибка`, а обход и построение остальных снимков продолжаются.

Каждое необязательное свойство физического кадра читается независимо в отдельном
блоке `Попытка/Исключение`. Ошибка чтения одного свойства не удаляет уже собранные
значения и не препятствует чтению остальных.

## Тестирование

Тесты должны подтвердить:

- прямое создание класса и отклонение неверного типа аргумента;
- отсутствие экспортных полей и наличие всех восьми геттеров;
- распознавание собственных, контекстных, внешних и повреждённых кадров;
- отсутствие чужих параметров в `Данные()`;
- соответствие сообщения, положения и стека конкретному физическому кадру;
- независимость массивов, возвращаемых `Стек()`;
- сохранение снимка при недоступном необязательном свойстве;
- поле `СнимкиКадров` вместо `Кадры` в результате `ВСтруктуру()`;
- физический порядок и усечение цепочки после 64 кадров;
- отсутствие поля версии.

Полный набор проверяется командой `oneunit execute`.
