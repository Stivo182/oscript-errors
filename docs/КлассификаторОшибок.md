# КлассификаторОшибок

Классифицирует неструктурированные `ИнформацияОбОшибке` по добавленным правилам.
Коды этих правил экземпляр считает собственными.

## Создание

```bsl
Новый КлассификаторОшибок
```

Создаёт пустой классификатор. Правила добавляются методом `ДобавитьПравила` или
загружаются из поставщика, зарегистрированного методом `ДобавитьПоставщикаПравил`.

## Методы

### ДобавитьПравила

```bsl
.ДобавитьПравила(<Правила>)
```

Добавляет `Массив` или `ФиксированныйМассив` правил. Все добавленные наборы
участвуют в общем выборе по силе совпадения и приоритету. Классификатор сохраняет
значения правил в момент добавления, поэтому их последующее изменение не влияет
на классификацию.

### ДобавитьПоставщикаПравил

```bsl
.ДобавитьПоставщикаПравил(<Поставщик>)
```

Регистрирует тип или готовый объект поставщика с методом `Все()`. Метод должен
возвращать `Массив` или `ФиксированныйМассив` объектов
`ПравилоКлассификацииОшибок`.

Регистрация типа:

```bsl
Классификатор = Новый КлассификаторОшибок;
Классификатор.ДобавитьПоставщикаПравил(Тип("ПравилаПриложения"));
```

Для типа требуется конструктор без параметров. Классификатор создаст объект
при первой классификации.

Регистрация готового объекта:

```bsl
Поставщик = Новый ПравилаПриложения(Настройки);
Классификатор = Новый КлассификаторОшибок;
Классификатор.ДобавитьПоставщикаПравил(Поставщик);
```

При регистрации объекта метод `Все()` также не вызывается. Успешно загруженные
правила и подготовленный индекс кешируются. Если загрузка завершилась ошибкой,
следующая классификация повторит загрузку.

Регистрации сохраняются в порядке добавления, но порядок не устраняет конфликт
разных кодов.

### Классифицировать

```bsl
.Классифицировать(<Ошибка>)
```

Возвращает нормализованную ошибку или `Неопределено`. Порядок обработки:

1. Ленивая подготовка поставщиков правил.
2. Корневая ошибка с собственным кодом.
3. Собственные структурированные коды во вложенных кадрах.
4. Все добавленные правила.

Для совпадений одной силы с разными кодами нужен однозначный результат. Большее
значение `Приоритет` правила разрешает такой конфликт. При равных приоритетах
классификатор возвращает `Неопределено`.

## Практический пример

Правило распознаёт ошибку HTTP-запроса. Адрес и длительность ожидания в её тексте
меняются, но начало сообщения и причина таймаута остаются постоянными.

```bsl
Правила = Новый Массив;
Правила.Добавить(
    Новый ПравилоКлассификацииОшибок()
        .НачинаетсяС("Ошибка HTTP-запроса:")
        .Содержит("Connection timed out")
        .КлассифицируетКак(
            КодыСтандартныхОшибок.ИстеклоВремяОжиданияСоединения(),
            "Истекло время ожидания соединения"
        )
);

Классификатор = Новый КлассификаторОшибок;
Классификатор.ДобавитьПравила(Правила);

Попытка
    ВызватьИсключение
        "Ошибка HTTP-запроса: https://api.example.org/users. Connection timed out after 30 seconds";
Исключение
    ИсходнаяОшибка = ИнформацияОбОшибке();
    НормализованнаяОшибка = Классификатор.Классифицировать(ИсходнаяОшибка);

    Если НормализованнаяОшибка <> Неопределено Тогда
        КодОшибки = ДиагностикаОшибок.КодОшибки(НормализованнаяОшибка);
        Сообщить(КодОшибки);
    КонецЕсли;
КонецПопытки;
```

В результате `ДиагностикаОшибок.КодОшибки()` вернёт `connection.timeout`, а
`НормализованнаяОшибка.Причина` будет ссылаться на `ИсходнаяОшибка`.
`ВызватьИсключение` использован только для демонстрации: в прикладном коде на его
месте будет HTTP-запрос или другая операция, которая может завершиться такой ошибкой.

## Результат классификации

При совпадении классификатор создаёт новый внешний кадр вида `Ошибка`:

- `КодОшибки` берётся из правила;
- поле `Сообщение` получает локализованное `ОписаниеОшибки` правила;
- `Данные.Источник` получает значение `ПравилаКлассификации`;
- `Данные.Правило` содержит явный или автоматический идентификатор;
- `Данные.НативныйТип` добавляется, если нативный тип известен для совпавшего кадра;
- `Причина` ссылается на исходную `ИнформацияОбОшибке`, переданную в `Классифицировать()`.

Исходная цепочка не изменяется и полностью сохраняется как причина нового кадра. Поэтому
нормализованный код удобен прикладному коду, а исходные сообщения и стек остаются доступны
диагностике.

## Выбор правила

Сила определяется источником совпадения. Классификатор сначала оставляет кандидатов
максимальной силы и только затем сравнивает `Приоритет`.

От более сильного к более слабому совпадения располагаются так:

1. Собственный структурированный код во вложенном кадре.
2. Правило с .NET-типом в физическом кадре.
3. Правило с .NET-типом в кадре, восстановленном из подробного представления.
4. Текстовое правило.

Все текстовые способы имеют одинаковую силу. Например, точное совпадение текста само по
себе не сильнее совпадения по префиксу.

Произвольно большой `Приоритет` не может победить кандидата большей силы. Среди кандидатов
максимальной силы выбирается наибольший приоритет. Если после этого остаются совпадения
одного кода, результат однозначен. Если остаются разные коды, `Классифицировать()` возвращает
`Неопределено`.

## Подготовка и проверка правил

При `ДобавитьПравила()` классификатор сразу проверяет правила, строит неизменяемый индекс и
сохраняет подготовленные значения полей. Изменение объекта правила или исходного массива после
успешного добавления не влияет на классификацию.

Для поставщика, зарегистрированного через `ДобавитьПоставщикаПравил()`, проверка и снимок
создаются при первой успешной ленивой загрузке. После этого правила и индекс кешируются;
последующие изменения объектов поставщика не меняют подготовленный набор.

Проверка завершается структурированной ошибкой в следующих случаях:

- не задан код или описание результата `КлассифицируетКак()`;
- `Приоритет` типа, отличного от `Число`, приводит к `argument.invalid_type`;
- точное сообщение сочетается с префиксом, фрагментом или окончанием;
- у текстового правила без `СНативнымТипом()` не задан `НачинаетсяС()`.

Пустые необязательные и неиспользуемые поля допустимы. Локализованные поля разбираются
при подготовке индекса, и для каждого языка определяется полный согласованный набор.
