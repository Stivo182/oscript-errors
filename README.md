`errors` - библиотека структурированных ошибок для OneScript.

Она дополняет стандартную `ИнформацияОбОшибке` средствами для создания, распространения и диагностики ошибок:
стабильными машинными кодами, структурированными данными, контекстом выполнения, подсказками и представлением
цепочки причин.

С помощью библиотеки можно:

- обрабатывать ошибки по стабильному коду, не анализируя текст сообщения;
- использовать готовый каталог стандартных ошибок аргументов, операций, ресурсов, сети и данных;
- сохранять исходную причину при переходе между уровнями приложения;
- добавлять контекст без изменения кода исходной ошибки;
- прикреплять к ошибкам структурированные диагностические данные;
- находить нужные ошибки и группы ошибок во всей цепочке причин;
- формировать пользовательское и диагностическое представления;
- проверять контракты аргументов с помощью стандартных структурированных ошибок;
- классифицировать неструктурированные исключения по декларативным правилам.

## Требования

- OneScript 2.0.0 или новее;
- OPM для установки зависимостей и сборки пакета.

## Установка

Установите пакет из OPM:

```shell
opm install errors
```

После установки подключите пакет в сценарии:

```bsl
#Использовать errors
```

Для проекта с файлом `packagedef` добавьте зависимость:

```bsl
Описание.ЗависитОт("errors");
```

## Типовые задачи

### Обернуть исходное исключение

На границе приложения задайте стабильный предметный код, сохранив исходную ошибку в цепочке причин:

```bsl
#Использовать errors

Попытка
	Порт = Число("не число");
Исключение
	ВызватьИсключение ФабрикаОшибок.Обернуть(
		ИнформацияОбОшибке(),
		"config.invalid_port",
		"Некорректное значение порта"
	);
КонецПопытки;
```

Пользовательское представление содержит код и сообщение приложения:

```text
config.invalid_port: Некорректное значение порта
```

Исходное исключение остаётся доступно через [`ДиагностикаОшибок`](docs/ДиагностикаОшибок.md).

### Создать структурированную ошибку

Новая ошибка может содержать машинный код, сообщение и произвольные данные:

```bsl
Ошибка = ФабрикаОшибок.Создать(
	"validation.invalid_email",
	"Некорректный адрес электронной почты",
	Новый Структура("Адрес", Адрес)
);

ВызватьИсключение Ошибка;
```

Код предназначен для программной обработки, а сообщение можно изменять и локализовывать независимо от него.

### Использовать стандартную ошибку

[`СтандартныеОшибки`](docs/СтандартныеОшибки.md) предоставляет именованные фабрики для распространённых сбоев.
Они возвращают готовую `ИнформацияОбОшибке` с локализованным сообщением и стабильным кодом:

```bsl
Ошибка = СтандартныеОшибки.РесурсНеНайден("config.json");
ВызватьИсключение Ошибка;
```

Такая ошибка имеет код `resource.not_found`. Для обработки без строковых литералов используйте
[`КодыСтандартныхОшибок`](docs/КодыСтандартныхОшибок.md):

```bsl
Если ДиагностикаОшибок.Содержит(Ошибка, КодыСтандартныхОшибок.РесурсНеНайден()) Тогда
	// Обработка отсутствующего ресурса
КонецЕсли;
```

Если стандартную ошибку нужно дополнить данными, подсказкой или URL, используйте одноимённую функцию модуля
`ПостроителиСтандартныхОшибок`:

```bsl
Ошибка = ПостроителиСтандартныхОшибок.РесурсНеНайден("config.json")
	.Данные("Каталог", КаталогНастроек)
	.Подсказка("Проверьте путь к файлу")
	.Построить();
```

Полный каталог фабрик и рекомендации по выбору близких кодов приведены в
[руководстве по стандартным ошибкам](docs/СтандартныеОшибки.md).

### Классифицировать неструктурированную ошибку

Декларативные правила присваивают стабильный код сообщениям внешних исключений.
Например, путь файла меняется, но тип ошибки, начало и окончание её сообщения остаются
постоянными:

```bsl
Правила = Новый Массив;
Правила.Добавить(
	Новый ПравилоКлассификацииОшибок
		.СНативнымТипом("System.IO.IOException")
		.НачинаетсяС("ru = 'Файл '''; en = 'The file '''")
		.ОканчиваетсяНа("ru = ''' уже существует.'; en = ''' already exists.'")
		.СИдентификатором("filesystem.already_exists.file_path")
		.КлассифицируетКак(
			"filesystem.already_exists",
			"ru = 'Файл уже существует'; en = 'File already exists'"
		)
);

Классификатор = Новый КлассификаторОшибок;
Классификатор.ДобавитьПравила(Правила);

Попытка
	ВыполнитьВнешнююОперациюСФайлом();
Исключение
	ИсходнаяОшибка = ИнформацияОбОшибке();
	// Например: External exception (System.IO.IOException): Файл 'report.json' уже существует.

	НормализованнаяОшибка = Классификатор.Классифицировать(ИсходнаяОшибка);
КонецПопытки;
```

Классификатор выделит из исходной ошибки тип `System.IO.IOException` и внутренний текст
`Файл 'report.json' уже существует.`. Правило проверит тип, префикс и окончание текста,
а путь файла между ними останется произвольным. Результатом будет ошибка со стабильным
кодом `filesystem.already_exists`.


Чтобы подключить отдельный набор правил, зарегистрируйте тип поставщика с методом `Все()`:

```bsl
Классификатор.ДобавитьПоставщикаПравил(Тип("ПравилаОшибокШлюза"));
```

Регистрируйте тип поставщика, если ему не нужны параметры конструктора. Передавайте
готовый объект, когда правила зависят от настроек или других объектов. Примеры создания
и подключения наборов правил приведены в
[КлассификаторОшибок](docs/КлассификаторОшибок.md).

### Добавить контекст

Контекст описывает выполнявшуюся операцию, но сохраняет код исходной ошибки:

```bsl
Ошибка = ФабрикаОшибок.ОбернутьКонтекстом(
	Ошибка,
	"Загрузка профиля пользователя",
	Новый Структура("Идентификатор", ИдентификаторПользователя)
);
```

Если на границе подсистемы нужен новый код, используйте `ФабрикаОшибок.Обернуть()`.

### Настроить ошибку через построитель

[`ПостроительОшибки`](docs/ПостроительОшибки.md) подходит для поэтапного добавления данных, подсказки, URL и причины:

```bsl
Ошибка = Новый ПостроительОшибки("http.proxy_error", "Не удалось подключиться через прокси")
	.Данные("Адрес", АдресПрокси)
	.Подсказка("Проверьте адрес прокси и сетевое подключение")
	.URL("https://example.org/errors/http-proxy-error")
	.Причина(Причина)
	.Построить();
```

Пользовательское представление содержит код, сообщение, подсказку и URL:

```text
http.proxy_error: Не удалось подключиться через прокси

Подсказка:
  Проверьте адрес прокси и сетевое подключение

URL:
  https://example.org/errors/http-proxy-error
```

### Найти ошибку в цепочке

Разбор один раз просматривает цепочку и предоставляет выборки ошибок, контекстов и снимков кадров:

```bsl
Разбор = ДиагностикаОшибок.Разобрать(Ошибка);

Если Разбор.Ошибки().Содержит("network.timeout") Тогда
	Сообщить(Разбор.ПользовательскоеПредставление());
КонецЕсли;
```

Для простой проверки без сохранения разбора используйте фасад:

```bsl
Если ДиагностикаОшибок.Содержит(Ошибка, "network.timeout") Тогда
	Сообщить("Сервис не ответил вовремя");
КонецЕсли;
```

### Проверить аргументы

[`ПроверкаАргументов`](docs/ПроверкаАргументов.md) выбрасывает стандартные структурированные ошибки при нарушении
контракта:

```bsl
ПроверкаАргументов.ПроверитьТип("Порт", Порт, Тип("Число"));
ПроверкаАргументов.ПроверитьДиапазон("Порт", Порт, 1, 65535);
```

Например, неверный тип приводит к ошибке со стабильным кодом `argument.invalid_type`.

### Настроить формат необработанных исключений

По умолчанию свойство `ИнформацияОбОшибке.Описание` содержит пользовательское представление. Полную диагностику
можно включить без изменения кода приложения:

```text
ONESCRIPT_ERRORS_FORMAT=diagnostic
```

Для выбора отдельных разделов используйте составной режим:

```text
ONESCRIPT_ERRORS_FORMAT=sections
ONESCRIPT_ERRORS_SECTIONS=current,causes,stack
```

Диагностические форматы могут раскрывать данные ошибки и стек вызовов. Правила и список разделов приведены в
[руководстве по представлению ошибок](docs/ПредставлениеОшибок.md#формат-необработанных-исключений).
