# errors

`errors` - библиотека структурированных ошибок для OneScript. Она дополняет стандартную
`ИнформацияОбОшибке` стабильным кодом ошибки, пользовательскими данными и контекстом выполнения.

Библиотека помогает:

- отделять код ошибки от текста сообщения;
- передавать вместе с ошибкой произвольные данные;
- добавлять контекст без изменения кода исходной ошибки;
- оборачивать причины новым кодом на границах подсистем;
- исследовать и выводить всю цепочку причин.

## Требования

- OneScript 2.0.0 или новее;
- OPM для установки пакета.

## Установка

Установите пакет из OPM:

```console
opm install errors
```

Для проекта с файлом `packagedef` добавьте зависимость:

```bsl
Описание.ЗависитОт("errors");
```

Подключите библиотеку в сценарии:

```bsl
#Использовать errors
```

## Быстрый старт

Преобразуйте аргумент `port` в число и оберните возможную ошибку кодом приложения:

```bsl
#Использовать errors

Попытка
    ЗначениеПорта = АргументыКоманднойСтроки[0];
    Порт = Число(ЗначениеПорта);
Исключение
    ВызватьИсключение ФабрикаОшибок.Обернуть(
        ИнформацияОбОшибке(),
        "config.invalid_port",
        "Некорректное значение порта"
    );
КонецПопытки;
```

Ошибка `config.invalid_port` и исходная причина останутся доступны в цепочке для обработки на внешнем уровне.

## Создание ошибок

### Новая ошибка

`Создать()` начинает новую цепочку с кодом ошибки, сообщением, необязательными данными и подсказкой:

```bsl
Ошибка = ФабрикаОшибок.Создать(
    "validation.invalid_email",
    "Некорректный адрес электронной почты",
    Новый Структура("Адрес", Адрес),
    "Проверьте формат адреса"
);

ВызватьИсключение Ошибка;
```

`Создать()`, `СКонтекстом()` и `Обернуть()` возвращают стандартную `ИнформацияОбОшибке`. Результат можно
передать в `ВызватьИсключение` напрямую. После перехвата создайте исследователь для удобного доступа к типу,
данным, подсказке и всей цепочке:

```bsl
Попытка
    ВызватьИсключение Ошибка;
Исключение
    Исследователь = Новый ИсследовательОшибки(ИнформацияОбОшибке());
    Сообщить(Исследователь.КодОшибки());
    Сообщить(Исследователь.Подсказка());
КонецПопытки;
```

Код ошибки состоит из двух или более частей, разделённых точками. Каждый сегмент начинается с латинской
или кириллической буквы, а затем может содержать буквы, цифры и `_`. Регистр игнорируется.
Текст сообщения можно изменять и локализовывать независимо от кода.

### Добавление контекста

`СКонтекстом()` описывает выполнявшуюся операцию, не изменяя код ошибки в причине:

```bsl
Ошибка = ФабрикаОшибок.СКонтекстом(
    Причина,
    "Загрузка профиля пользователя",
    Новый Структура("Идентификатор", ИдентификаторПользователя)
);
```

### Оборачивание новым кодом

`Обернуть()` создаёт новый кадр с кодом ошибки и сохраняет переданную причину в цепочке:

```bsl
Ошибка = ФабрикаОшибок.Обернуть(
    Причина,
    "profile.load_failed",
    "Не удалось загрузить профиль",
    Новый Структура("Идентификатор", ИдентификаторПользователя)
);
```

После такого оборачивания эффективным кодом будет `profile.load_failed`, но
`Исследователь.ЕстьОшибка()` сможет найти и код исходной причины.

### Fluent-конструктор

Для поэтапной настройки ошибки используйте `КонструкторОшибки` напрямую или получите его из фабрики:

```bsl
Ошибка = ФабрикаОшибок.Конструктор("http.proxy_error", "Не удалось подключиться через прокси")
    .Данные("Адрес", АдресПрокси)
    .Подсказка("Проверьте переменную HTTPS_PROXY")
    .Причина(Причина)
    .Построить();
```

Без вызова `Причина()` конструктор создаёт новую цепочку. С указанной причиной он создаёт обёрнутую ошибку.
`Данные(Ключ, Значение)` поэтапно формирует структуру; повторный ключ заменяет ранее установленное значение.
Для готового произвольного значения используйте `ПроизвольныеДанные(Значение)`. Эти два режима нельзя смешивать
в одном конструкторе. Повторный вызов остальных fluent-методов заменяет ранее установленное значение.

## Стандартные ошибки

Стандартные типы универсальны: они не получают пространство имён библиотеки-потребителя. Благодаря этому разные
библиотеки могут одинаково обрабатывать инфраструктурную ошибку. Для 30 наиболее востребованных типов доступны
именованные фабрики:

| Фабрика | Тип ошибки | Поля `Данные` |
| --- | --- | --- |
| `НеверныйТипАргумента` | `argument.invalid_type` | `ИмяАргумента`, `ОжидаемыйТип`, `ФактическийТип` |
| `АргументНеЗаполнен` | `argument.required` | `ИмяАргумента` |
| `НедопустимоеЗначениеАргумента` | `argument.invalid_value` | `ИмяАргумента`, `Ожидание` |
| `АргументВнеДиапазона` | `argument.out_of_range` | `ИмяАргумента`, `ОжидаемыйДиапазон` |
| `ОперацияОтменена` | `operation.cancelled` | `ИмяОперации` |
| `ОперацияВНедопустимомСостоянии` | `operation.invalid_state` | `ИмяОперации` |
| `ОперацияНеРеализована` | `operation.not_implemented` | `ИмяОперации` |
| `ОперацияНеПоддерживается` | `operation.not_supported` | `ИмяОперации` |
| `ИстеклоВремяОжиданияОперации` | `operation.timeout` | `ИмяОперации` |
| `ОперацияНедоступна` | `operation.unavailable` | `ИмяОперации` |
| `ДоступЗапрещен` | `access.denied` | `ИмяРесурса` |
| `РесурсНеНайден` | `resource.not_found` | `ИмяРесурса` |
| `РесурсУжеСуществует` | `resource.already_exists` | `ИмяРесурса` |
| `РесурсУжеИспользуется` | `resource.already_in_use` | `ИмяРесурса` |
| `РесурсЗакрыт` | `resource.closed` | `ИмяРесурса` |
| `РесурсИсчерпан` | `resource.exhausted` | `ИмяРесурса` |
| `РесурсНеПуст` | `resource.not_empty` | `ИмяРесурса` |
| `ВозможностьНедоступна` | `feature.unavailable` | `ИмяВозможности` |
| `СоединениеОтклонено` | `connection.refused` | `Узел` |
| `СоединениеСброшено` | `connection.reset` | `Узел` |
| `СоединениеЗакрыто` | `connection.closed` | `Узел` |
| `ИстеклоВремяОжиданияСоединения` | `connection.timeout` | `Узел` |
| `СетевоеИмяНеНайдено` | `network.name_not_found` | `СетевоеИмя` |
| `НекорректныеДанные` | `data.invalid` | `ИмяДанных` |
| `ДанныеСлишкомБольшие` | `data.too_large` | `ИмяДанных`, `Ограничение` |
| `ДанныеПовреждены` | `data.corrupt` | `ИмяДанных` |
| `НевернаяКодировкаДанных` | `encoding.invalid` | `ИмяДанных`, `Кодировка` |
| `КодировкаНеПоддерживается` | `encoding.not_supported` | `Кодировка` |
| `НеизвестнаяКодировка` | `encoding.unknown` | `Кодировка` |
| `НарушенВнутреннийИнвариант` | `internal.invariant_violation` | `Инвариант` |

Для проверки входных параметров используйте единственный публичный guard-модуль `ПроверкаАргументов`:

```bsl
ПроверкаАргументов.ПроверитьТип("Порт", Порт, Тип("Число"));
ПроверкаАргументов.ПроверитьЗаполненность("Адрес", Адрес);
ПроверкаАргументов.ПроверитьДопустимость("Порт", Порт >= 1 И Порт <= 65535, "число от 1 до 65535");
ПроверкаАргументов.ПроверитьДиапазон("Порт", Порт, 1, 65535);
```

`ПроверитьДиапазон` использует включительные границы и поддерживает числа и даты. Фактическое значение в ошибке
не сохраняется. Успешные проверки ничего не возвращают, а их параметры проходят структурированные проверки
собственных контрактов.

Состояние операции, наличие ресурса, размер и целостность данных, поддержку кодировки, сравнение, вхождение и
содержание проверяйте в вызывающем коде. При нарушении сразу выбрасывайте ошибку из подходящей именованной
фабрики:

```bsl
Если Не ФайлСуществует(ПутьНастроек) Тогда
    ВызватьИсключение ФабрикаОшибок.РесурсНеНайден("Настройки приложения");
КонецЕсли;

Если Не ПоддерживаетсяКодировка(Кодировка) Тогда
    ВызватьИсключение ФабрикаОшибок.КодировкаНеПоддерживается(Кодировка);
КонецЕсли;
```

Если ошибку нужно сформировать без немедленного исключения, используйте фабрику:

```bsl
ОшибкаТипа = ФабрикаОшибок.НеверныйТипАргумента("Порт", "Число", Порт);
ОшибкаЗаполнения = ФабрикаОшибок.АргументНеЗаполнен("Адрес");
ОшибкаЗначения = ФабрикаОшибок.НедопустимоеЗначениеАргумента("Порт", "число от 1 до 65535");
ОшибкаРесурса = ФабрикаОшибок.РесурсНеНайден("Настройки приложения");
ОшибкаСоединения = ФабрикаОшибок.ИстеклоВремяОжиданияСоединения("Сервис оплаты");
```

Все диагностические параметры именованных фабрик и `Сообщение` — строки; диагностические параметры должны быть
непустыми. Исключение — `ФактическоеЗначение` функции `НеверныйТипАргумента`, оно может иметь любой тип. Функции
возвращают `ИнформацияОбОшибке`, совместимую с `ВызватьИсключение`, и сами исключение не вызывают. При нарушении
собственного контракта они создают структурированную ошибку `argument.invalid_type` или `argument.required`.

Фабрики сохраняют только перечисленные в таблице поля. Фактические значения, содержимое данных, исходные
исключения, сетевые ответы, полные URI и реквизиты доступа автоматически не записываются. Имена ресурсов, узлов и
другие диагностические строки передавайте в безопасном для журналирования виде.

Стандартные сообщения заданы через `НСтр` на русском и английском языках. Вариант выбирается настройкой
OneScript `systemLanguage` (`ru` или `en`); машинный тип ошибки при этом не меняется. Можно передать собственное
сообщение последним параметром фабрики или guard-процедуры.

Ещё 13 кодов каталога стабильны, но пока не имеют именованных фабрик: `argument.ambiguous`,
`argument.not_iterable`, `argument.incompatible`, `result.invalid_property`, `result.invalid_property_value`,
`result.invalid_value`, `operation.failed`, `operation.interrupted`, `operation.concurrent`,
`resource.invalid_kind`, `system.error`, `assertion.failed`, `error.unhandled`. Создавайте их общим методом
`ФабрикаОшибок.Создать`, передавая только безопасные предметные данные.

Выбирайте наиболее точный тип по причине сбоя: `argument.*` — контракт вызывающего кода, `operation.*` — ход или
состояние операции, `resource.*` и `access.*` — ресурс и доступ к нему, `connection.*` и `network.*` — соединение и
разрешение имени, `data.*` и `encoding.*` — содержимое и представление данных. `internal.invariant_violation`
обозначает дефект программы. Предметные ошибки приложения сохраняют собственное пространство имён; при переходе
границы приложения стандартную причину можно обернуть предметной ошибкой.

## Поиск в цепочке

Создайте исследователь: он один раз просмотрит физическую цепочку и сохранит безопасные снимки кадров.
`НайтиОшибку()` возвращает первый снимок указанного типа, а `НайтиОшибки()` — неизменяемую выборку всех
вхождений одного или нескольких типов:

```bsl
Исследователь = Новый ИсследовательОшибки(Ошибка);
Выборка = Исследователь.НайтиОшибки(
    "database.timeout, network.timeout"
);

Для Каждого Снимок Из Выборка.Все() Цикл
    Сообщить(Снимок.КодОшибки() + ": " + Снимок.Сообщение());
КонецЦикла;
```

Типы разделяются запятыми, пробелы рядом с запятыми игнорируются. Регистр не учитывается. Результат содержит
снимки в физическом порядке от внешнего кадра к корневому. Исходную `ИнформацияОбОшибке` можно получить через
`Снимок.ИсходнаяОшибка()`. Если совпадений нет, возвращается пустая выборка.

## Представление ошибок

Методы представления вызываются у исследователя. `КраткоеПредставление()` предназначено для консоли и обычных
логов. Оно выводит код эффективной ошибки, предшествующие ей контексты и сообщение:

```bsl
Исследователь = Новый ИсследовательОшибки(Ошибка);
Сообщить(Исследователь.КраткоеПредставление());
Сообщить(Исследователь.ПодробноеПредставление());
```

```text
profile.load_failed: Загрузка профиля -> Не удалось загрузить профиль
```

`ПодробноеПредставление()` формирует диагностический отчёт по просмотренной цепочке. Внешний кадр выводится
первым, следующие кадры объединяются в блок `Причина`, а общий стек первого физического кадра располагается в
конце:

```text
profile.load_failed: Не удалось загрузить профиль
  Данные:
    Идентификатор: 42

  Причина:
    1: Сервер закрыл соединение
    2: network.timeout: Превышено время ожидания

  Подсказка:
    Повторите запрос

  Стек вызовов:
    1: ЗагрузитьПрофиль:42
    2: ЗапуститьПриложение:10
```

Если причина или строка стека одна, номер не выводится. Подробное представление не ограничивает длину строк и
раскрывает содержимое `Данных` без маскирования. Не помещайте в диагностируемые данные пароли, токены и другие
сведения, которые нельзя записывать в лог.

### Структурированное представление

`ИсследовательОшибки.ВСтруктуру()` возвращает данные цепочки без объектов `ИнформацияОбОшибке`, поэтому результат
можно передать сериализатору или обработать программно:

```bsl
Исследователь = Новый ИсследовательОшибки(Ошибка);
СтруктураОшибки = Исследователь.ВСтруктуру();
```

В результате находятся `Цепочка` в физическом порядке от внешнего к корневому, `ЭффективнаяОшибка`, признак
`ЦепочкаУсечена` и общий `Стек` внешнего физического кадра. Каждый кадр содержит вид, тип, сообщение, данные,
подсказку и место возникновения. Кадры общего стека преобразуются в структуры с полями `ИмяМодуля` и
`НомерСтроки`.

Значение `Данные` передаётся без копирования и дополнительного преобразования. Библиотека намеренно не зависит от
конкретного формата обмена: при необходимости полученную структуру можно сериализовать в JSON библиотекой `jason`
или любым другим сериализатором, подходящим приложению.
